# Long-horizon plan — v0.3.0 "Frontier"

**Created:** 2026-11-04
**Owner:** hcsmedia / timfromhcs
**Starting point:** `318e509` (v0.2.0, `main`, clean tree, green local gate)
**Target:** a release that is credible on every surface it ships — browser, Windows/Linux/macOS
desktop, Node CLI, Python package, npm packages, MCP — with real physics beyond noble gases,
real materials data, GPU execution, and packaging that a stranger can install.
**Version decision:** the plan originally targeted 1.0.0 **conditionally**. Two planned P0
items (Miller-index slabs, cubic elastic constants) were deferred to 1.1 because they need
their own geometry/strain test suites; shipping them untested would be worse than an honest
0.3.0. The all-platform release therefore ships as **0.3.0 "Frontier"**, and 1.0.0 stays gated
on those two items plus an external API-stability commitment.

This document is the working contract for the release. Every phase has a gate with a command
and a pass criterion. A phase without evidence is not done. Anything that slips is moved to
the v1.1 backlog explicitly — never silently deleted.

### Phase 1 — Many-body physics: Stillinger–Weber silicon (P0)

**Why:** the single largest credibility gap. A materials studio whose only engine handles
argon is a demo. SW silicon is a published, widely used many-body potential with a small,
citable parameter set and no external dependency.

**Design**

- New module `packages/core/src/kernels/sw.ts`:
  - two-body term `εA[B(σ/r)^p − (σ/r)^q]·exp(σ/(r − aσ))`, cutoff `aσ`;
  - three-body term `ελ(cosθ + 1/3)²·exp(γσ/(r_ij − aσ))·exp(γσ/(r_ik − aσ))`, summed over
    each central atom and unordered neighbour pairs;
  - analytic forces, with the derivative accumulated per pair direction;
  - neighbour list within `aσ`, rebuilt when a displacement guard is exceeded;
  - same `EnergyForces` contract as LJ (`backend`, `pairCount`, `cutoff`, `cutoffReduced`).
- New model record `sw.silicon.v1` with the 1985 parameter set and its citation.
- Engine record `hcs.sw-silicon` (classical_model, Si only) added to the registry; it must be
  selectable in the studio and CLI, and must refuse every non-Si species.
- Extend the worker/CLI kernel dispatch by `model_id`, not by engine guesswork.

**Tests**

1. Two-body term equals the closed form at a set of radii; derivative equals the numerical
   derivative (rel. < 1e-6).
2. Three-body term for a hand-built 3-atom cluster equals an independently written reference
   expression (abs < 1e-12 eV).
3. Forces equal −∇E by central differences on a 64-atom Si cell (rel. < 1e-5).
4. Energy is translation-invariant (abs < 1e-9 eV) and the net force is zero (< 1e-9 eV/Å).
5. Diamond Si at a = 5.431 Å has a cohesive energy inside the literature bracket
   (−5.5 … −4.0 eV/atom) and a maximum force below 0.05 eV/Å at the ideal geometry.
6. A relax from a 2 % strained cell returns to a lattice constant within 0.10 Å of 5.431.
7. NVE on 64 atoms conserves total energy (< 1e-3 eV/atom over 200 steps).
8. Non-Si species are refused with the element named, never silently dropped.

**Gate 1:** the new tests plus the existing parity suite are green; the CLI produces a Si
energy/relax/MD record with `engine_id: hcs.sw-silicon` and a provenance record that names the
parameter source; a benchmark entry records atoms/s.

### Phase 2 — Finite temperature: Langevin NVT (P0)

**Why:** every credible MD workflow needs a thermostat. v0.2.0 rejected NVT honestly; 1.0.0
should implement one correctly instead of rejecting it.

**Design**

- `runMd` gains `ensemble: "NVE" | "NVT"` and `thermostat: { targetTemperature, friction }`.
- BAOAB splitting for Langevin: half-kick, half-drift, Ornstein–Uhlenbeck velocity update with
  `c1 = exp(−γΔt)`, `c2 = sqrt(k_B T (1 − c1²)/m)`, half-drift, half-kick.
- Reproducible from the seed: the same seed and checkpoint reproduce the same trajectory.
- The result records `thermostate: "NVE" | "NVT(langevin)"`, the target temperature, the
  friction and the realised mean temperature.
- The job layer accepts NVT for `hcs.lj-reference` and `hcs.sw-silicon`; NPT remains refused
  with `unsupported_ensemble` naming the missing barostat.

**Tests**

1. Mean temperature over 2 000 steps is within 5 % of target for both engines.
2. Equipartition: mean kinetic energy per degree of freedom ≈ ½k_BT (5 %).
3. Same seed ⇒ bit-identical trajectory; different seed ⇒ different trajectory.
4. Checkpoint/resume in NVT reproduces a continuous run bit-for-bit (the OU update must be
   derived from the checkpointed RNG state, not from wall-clock time).
5. NPT is refused with a typed error, not silently run as NVT.
6. Energy conservation is _not_ claimed for NVT; the result must not report a drift failure.

**Gate 2:** tests green; the Workbench exposes NVT with target temperature and friction, shows
the realised temperature, and the E2E test runs one NVT job.

### Phase 3 — Characterization: XRD and elastic constants (P0)

**Why:** users judge a materials tool by what it can _show_. XRD is the cheapest real
characterization with an exact closed form and a checkable reference (Si 111 at 28.44° for
Cu Kα).

**Design**

- `packages/core/src/kernels/xrd.ts`:
  - Bragg angle from d-spacing for a given wavelength; structure factor
    `F_hkl = Σ f_j exp(2πi(h·x_j + k·y_j + l·z_j))` with atomic form factors (Cromer–Mann
    coefficients for the supported elements, or a documented analytic approximation);
  - Lorentz–polarisation factor, multiplicity from the lattice metric;
  - 2θ range, step, wavelength and profile (Gaussian FWHM) as explicit parameters;
  - output: peak list (hkl, d, 2θ, intensity, multiplicity) + a sampled pattern series.
- `packages/core/src/kernels/elastic.ts` for cubic cells: six independent strain modes,
  energy curvature `C_ij = (1/V)·∂²E/∂ε_i∂ε_j` at the relaxed geometry; refuse non-cubic cells
  instead of reporting a meaningless number.
- UI: a Characterization panel in Structure Studio (XRD plot + peak table) and a Workbench
  result card for elastic constants.
- Validation: Si 111/220/311 positions within 0.05° of the reference; NaCl 200/220 ratios;
  cubic Cu elastic constants within 15 % of literature for the EAM-free LJ model is _not_
  claimed — the test uses analytic consistency (Born stability, symmetry of the tensor).

**Gate 3:** XRD unit tests against Si and NaCl; E2E downloads an XRD pattern; elastic constants
are either correct for a documented model or absent (never a fabricated number).

### Phase 4 — Surfaces: Miller-index slab builder (P0)

**Why:** surfaces are where materials work actually happens (catalysis, growth, corrosion).
A studio without slabs is a bulk-only toy.

**Design**

- `packages/core/src/build.ts`: `makeSlab(structure, { miller: [h,k,l], layers, vacuum, shift })`
  for orthogonal cells (cubic/orthorhombic/tetragonal), with:
  - in-plane lattice vectors from the Miller plane, a supercell large enough to contain the
    rotated cell, cut by the interplanar spacing;
  - `layers` repeats along the surface normal; `vacuum` adds a gap and sets `pbc[2] = false`;
  - deterministic site ordering and a new structure id; the source notes the plane and vacuum.
- Non-orthogonal cells are refused with a typed message; hexagonal slabs are v1.1.
- UI: Slab builder in Structure Studio with h/k/l, layers, vacuum, and a live atom count.
- Viewer: the cell box and PBC state must reflect the non-periodic axis.

**Tests**

1. Si(100) 1×1 slab has the expected 2 atoms per layer and the correct vacuum gap.
2. Si(111) slab has the correct in-plane lattice constant (a/√2) and no overlapping atoms.
3. Refuses a hexagonal cell with a reason.
4. Round-trip through POSCAR/XYZ preserves the non-periodic axis and the vacuum.
5. Atom count guard (≤ 20 000) is enforced.

**Gate 4:** tests green; an E2E test builds a slab, validates it, and exports it.

### Phase 5 — GPU: WebGPU energy/force kernel (P0)

**Why:** the only remaining compute tier the product claims but does not have. WebGPU is
mainstream in 2026 and the machine has a working adapter.

**Design**

- `packages/webgpu` (new workspace) with:
  - WGSL compute shader for the LJ pair loop: one invocation per pair block, atomics-free
    reduction via a two-stage tree (pair energies/forces into a workgroup buffer, then a
    second dispatch reduces);
  - f32 buffers, documented precision; positions and species uploaded once per evaluation;
  - a typed `WebGpuUnavailable` reason for every failure mode (no adapter, no device, shader
    validation, timeout);
  - a `backend: "webgpu"` result field and a cross-check against CPU for every job (tolerance
    1e-3 relative on energy, 1e-2 on forces, documented as f32).
- Worker dispatch: `auto` prefers WebGPU for energy/relax/MD when the cell is small enough and
  the adapter exists, falls back to WASM, then CPU; the chosen backend is recorded.
- Capability report and UI badge reflect the _actual_ selected backend, not adapter presence.

**Tests**

1. Adapter-less environment returns a typed unavailability, not a crash.
2. Energy/forces parity against CPU on 32 and 108 atoms within the f32 tolerance.
3. Determinism across two runs with the same input.
4. Fallback: forcing `cpu` never touches WebGPU; forcing `webgpu` without an adapter refuses
   instead of silently using CPU.
5. E2E: a job runs with `backend: webgpu` on this machine and the result says so; if the CI
   runner has no adapter, the test asserts the documented fallback instead of skipping silently.

**Gate 5:** tests green on this machine; the benchmark records WebGPU vs WASM vs CPU timings
with the parity delta; the UI never claims GPU when the fallback ran.

### Phase 7 — Data: OPTIMADE 1.3 connector (P1)

**Why:** a materials studio without a database import is an island. OPTIMADE is the only
federation standard worth implementing, and it is explicitly in scope as an optional connector.

**Design**

- `python/hcs_materials/src/hcs_materials/optimade.py`:
  - `OptimadeClient(base_url, timeout, cache_dir, user_agent, rate_limit)` using only the
    standard library (`urllib`) so the base package stays dependency-light;
  - endpoints: `/info`, `/links`, `/structures` with `filter`, `page_limit`, `page_offset`,
    `response_fields`, `sort`;
  - converts an entry to the HCS `Structure` (lattice, sites, species, `source` with provider,
    record id, URI, retrieval time and license);
  - disk cache keyed by the canonical query, with TTL; a token-bucket rate limit per host;
  - refuses non-HTTPS, non-allow-listed hosts by default and never sends credentials.
- CLI: `hcs-materials optimade providers|search|fetch --provider ... --filter ... --out ...`
  writes the structure plus a provenance sidecar.
- MCP: `optimade_search` and `optimade_fetch` (read-only, bounded, rate-limited), with the
  provider allow-list and the license in the response.
- Browser: a Data page that explains the CORS constraint (Q5) and offers "open in desktop/CLI"
  instead of a broken fetch.

**Tests**

1. `/info` parsing and version check against a recorded fixture.
2. Filter passthrough and pagination (two pages, no duplicates).
3. Cache hit does not hit the network; TTL expiry does.
4. Rate limit delays the second request (fake clock).
5. A real structure from a fixture converts to a valid HCS structure with provenance.
6. Non-HTTPS / unknown host / malformed JSON produce typed errors.
7. MCP tools are listed, bounded and read-only.

**Gate 7:** tests green; one real query against a live provider recorded in
`docs/plan/evidence/optimade-live.txt`; the imported structure validates and runs an energy job
when the model supports its elements.

### Phase 8 — Agent surface: MCP Streamable HTTP (P1)

**Why:** the spec moved to stateless HTTP in 2026-07-28; stdio-only is a real limitation for
remote/agent use, and the security model must be explicit.

**Design**

- `hcs-materials-mcp --transport streamable-http --host 127.0.0.1 --port <n> --token <t>`:
  - binds loopback only, refuses non-loopback without an explicit override;
  - requires a bearer token generated at startup (printed once), constant-time comparison;
  - emits `Mcp-Method` / `Mcp-Name` on responses and validates them on requests;
  - no session state; every request is self-contained;
  - request size limit, per-tool timeouts, and the existing workload budgets.
- A `--print-token` mode for tests, never logged by default.
- Docs: a threat-model delta and a client example.

**Tests**

1. Missing/invalid token ⇒ 401, no tool executes.
2. Non-loopback bind ⇒ refused unless `--allow-non-loopback`.
3. Header/body mismatch ⇒ 400.
4. `tools/list` and `tools/call` work over HTTP with the official client.
5. Oversized body ⇒ 413.
6. The stdio path is unchanged.

**Gate 8:** tests green; a recorded HTTP round-trip with the official SDK client.

## 5. Explicitly out of scope (and why)

| Item                                  | Why not now                                                                            |
| ------------------------------------- | -------------------------------------------------------------------------------------- |
| uMLIP inference (MACE/MatterSim/Orb)  | Hundreds of MB of PyTorch weights; no browser path; adapter only, clearly unavailable  |
| DFT (QE/CP2K/VASP)                    | Licensed/GB-scale installations; input generation is a project of its own              |
| NPT barostat                          | Requires cell dynamics and stress; a wrong barostat is worse than an honest refusal    |
| Full space-group detection (spglib)   | Native/Python bridge + validation matrix; lattice-metric symmetry ships instead        |
| Hexagonal slab builder                | Non-orthogonal plane construction needs its own geometry test suite                    |
| Code signing / notarization           | Requires paid certificates and CI secrets that do not exist here                       |
| Publishing to PyPI/npm                | No tokens; dry-run + workflows only, stated in the release notes                       |
| Generative discovery / hull screening | Needs a validated uMLIP and a reference dataset; out of scope until the adapter exists |

## 6. Risk register

| Risk                                | Probability | Impact            | Mitigation                                                                                  |
| ----------------------------------- | ----------- | ----------------- | ------------------------------------------------------------------------------------------- |
| SW force derivation error           | Medium      | Wrong physics     | Numerical-gradient test as the gate; hand-computed 3-atom reference; revert if it fails     |

| Tauri build needs network/toolchain | Medium      | No installer      | VS 2022 + WebView2 verified locally; CI matrix as backup; record the exact failing command  |
| Toolchain refresh breaks the studio | Medium      | Schedule slip     | One commit, full gate, revert immediately on red; TypeScript stays on 5.x                   |
| OPTIMADE provider changes/downtime  | Medium      | Flaky test        | Fixtures for tests; live check is evidence, not a CI dependency                             |
| Scope too large for one session     | High        | Partial release   | P0 phases first; P1 can ship as 0.3.0 with an explicit backlog; never fake a gate           |
| Vercel deployment quota             | Medium      | No production URL | Retry after the window; if refused, publish Git release and mark D3 blocked with the error  |
